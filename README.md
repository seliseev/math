# Устный счёт — пример авто-публикации на htmlkin.ru

Пример репозитория: статический сайт + GitHub Actions, который **публикует его на [htmlkin.ru](https://htmlkin.ru) при каждом обновлении ветки `main`**. Ничего собирать не нужно — в деплое участвуют исходные файлы как есть.

Живой результат: **https://math.htmlkin.ru**

Сам сайт — тренажёр устного счёта для детей: сложение и вычитание в пределах 10, 20 и 30 для детей.

## Что внутри

| Файл | Назначение |
| --- | --- |
| `index.html` | Страница «Счёт в пределах 10» |
| `20.html` | Страница «Счёт в пределах 20» |
| `app.js` | Общая логика; предел счёта берётся из `<body data-limit="...">` |
| `style.css` | Общие стили |
| `.github/workflows/deploy.yml` | Публикация на htmlkin.ru при push в `main` |

## Как работает деплой

Workflow [`deploy.yml`](.github/workflows/deploy.yml) запускается на push в `main` и вручную (кнопка **Run workflow**):

1. `actions/checkout` — забирает репозиторий;
2. `zip -r site.zip .` — упаковывает **всё содержимое репозитория**, кроме `.git/`, `.github/`, `.gitignore`, `README.md` и самих архивов;
3. `PUT /api/v1/pages/{id}` с архивом в поле `site_archive` — htmlkin **полностью заменяет** содержимое сайта новым набором файлов. Адрес сайта при этом не меняется.

Дополнительно:

- `concurrency: htmlkin-deploy` — два быстрых пуша подряд не устроят гонку, при которой поверх новой версии ляжет старая;
- при ответе не 2xx job падает и печатает `message` из ответа API;
- в Summary прогона попадает адрес сайта, число файлов и SHA коммита.

Новые файлы сайта достаточно положить в репозиторий — они попадут в архив автоматически, workflow править не нужно.

## Настройка у себя

### 1. API-ключ

Личный кабинет htmlkin → **API-ключи** → создать ключ. Он показывается **один раз**, скопируйте сразу.

> REST API доступен на тарифах **Оптимальный** и **Бизнес**. На бесплатном тарифе запросы отклоняются с `403 api_not_allowed`, и автопубликация работать не будет.

### 2. Первая публикация — получить `page_id`

Workflow умеет только **обновлять** существующий сайт, поэтому сайт нужно один раз создать. Из корня репозитория:

```bash
export HTMLKIN_API_KEY='<ваш ключ>'

zip -r site.zip . -x '.git/*' '.github/*' '.gitignore' 'README.md' '*.zip'

curl -X POST https://htmlkin.ru/api/v1/pages \
  -H "Authorization: Bearer $HTMLKIN_API_KEY" \
  -F "site_archive=@site.zip" \
  -F "subdomain=my-site"
```

В ответе придёт `id` — это и есть `page_id`, а `url` — адрес сайта:

```json
{ "id": "abc123", "url": "https://my-site.htmlkin.ru", "file_count": 4, "entry_path": "index.html" }
```

Субдомен опционален (без него выдаётся случайный), 3–63 символа `a-z`, `0-9`, `-`; занятый вернёт `409 subdomain_taken`.

Альтернатива без curl: опубликовать сайт через [MCP-сервер htmlkin](https://htmlkin.ru/docs/mcp) прямо из Claude или из веб-интерфейса — `page_id` будет в ответе и в личном кабинете.

### 3. Прописать ключ и `page_id` в репозиторий

Ключ — только в секреты, никогда в файлы репозитория:

```bash
gh secret set HTMLKIN_API_KEY --repo <owner>/<repo>
```

или через UI: **Settings → Secrets and variables → Actions → New repository secret**, имя `HTMLKIN_API_KEY`.

`page_id` секретом не является (адрес сайта и так публичный). Либо задайте переменную репозитория:

```bash
gh variable set HTMLKIN_PAGE_ID --repo <owner>/<repo> --body 'abc123'
```

либо впишите свой id прямо в `deploy.yml`, заменив значение по умолчанию:

```yaml
PAGE_ID: ${{ vars.HTMLKIN_PAGE_ID || 'abc123' }}
```

В этом репозитории по умолчанию указан id сайта `math.htmlkin.ru`; переменная `HTMLKIN_PAGE_ID`, если она задана, его перекрывает.

### 4. Проверить

```bash
git push origin main
```

Вкладка **Actions** → прогон **Deploy to htmlkin.ru**. В Summary будет адрес обновлённого сайта. Ручной перезапуск без коммита — **Run workflow** на той же вкладке.

## Ограничения htmlkin

- в корне сайта обязателен `index.html`;
- до 500 файлов, суммарный распакованный размер — по тарифу (до 50 МБ);
- частота запросов: 60/мин на «Оптимальном», 120/мин на «Бизнесе»;
- бинарные ассеты (картинки, шрифты) заливаются только ZIP-архивом — этот workflow как раз так и делает.

## Частые ошибки API

| HTTP | `error` | Что делать |
| --- | --- | --- |
| 401 | `invalid_api_key` | Секрет `HTMLKIN_API_KEY` не задан, протух или скопирован с пробелом |
| 403 | `api_not_allowed` | Тариф без API — нужен «Оптимальный» или «Бизнес» |
| 404 | `not_found` | `page_id` неверный или сайт принадлежит другому аккаунту |
| 400 | `missing_entry_file` | В корне архива нет `index.html` |
| 413 | `file_too_large` | Сайт больше лимита тарифа |
| 429 | `rate_limit_exceeded` | Слишком частые пуши; повторить после `Retry-After` |

Полная документация: [REST API](https://htmlkin.ru/docs/api), [MCP-сервер](https://htmlkin.ru/docs/mcp).
